## How I work

- Understand the existing system before rewriting it.
- Prefer simple solutions that are easy to explain and maintain.
- Treat debugging as an investigation, not a guessing game.
- Read the documentation before reaching for another abstraction.
- Build small tools when automation can remove repetitive work.
- Keep deployment and infrastructure concerns visible.
- Write code that another developer can understand months later.
- Learn the fundamentals behind the tool instead of only learning the tool itself.
- Build projects to understand concepts, not just to add them to a résumé.
